Clipper.Clipper — Module
Clipper

A Julia wrapper for the Clipper2 polygon-clipping and offsetting library.

This module exposes Clipper2's integer-coordinate API:

  • Clipper64, the boolean-operation engine
    • add_subject!/add_clip!/add_open_subject! to add geometry
    • ClipType/FillRule enums to specify Boolean operations
    • execute, execute_polytree, and clear!
  • ClipperOffset, the offsetting engine
    • add_path! to add geometry
    • JoinType and EndType enums to specify offsetting behavior
    • execute and clear!
  • Z-aware Point64Z input and execute_polytree_z results for vertex provenance
  • Free functions such as union_paths, intersect_paths, difference_paths, xor_paths, inflate_paths, and minkowski_sum

All geometry crosses the FFI boundary through the C shim libcclipper2 (cclipper2.cpp), which calls Clipper2's C++ API. Results are returned via Julia callbacks.

Clipping engine

Clipper.Clipper64 — Type
Clipper64(; preserve_collinear=true, reverse_solution=false)

A stateful boolean-operation engine. Add geometry with add_subject!, add_clip!, or add_open_subject!; compute a result with execute or execute_polytree; reuse after clear!.

preserve_collinear=true keeps output vertices that lie on a straight edge between their neighbours. Pass false for minimal-vertex contours. reverse_solution flips the orientation of output contours.

The underlying C++ engine is freed by a finalizer. Throws ClipperError if the engine cannot be created.

source
Clipper.add_subject! — Function
add_subject!(c, path_or_paths; closed=true)

Add closed (or, with closed=false, open) subject geometry to the engine. Returns c; throws ClipperError on failure. Single-path adds reject degenerate paths (closed paths need ≥ 3 vertices, open ≥ 2); batch adds pass everything through and leave degenerate paths to the engine, which ignores them.

Clipper.execute — Method
execute(c, cliptype, fillrule) -> (Paths64, Paths64)

Run the boolean operation cliptype with the single fillrule and return (closed, open) solution paths, both flat Paths64. (Clipper2 uses one fill rule for both subject and clip; open is empty unless open subjects were added.) Mirrors execute_polytree's two-part return.

source
Clipper.execute_polytree — Function
execute_polytree(c, cliptype, fillrule) -> (PolyTree64, Paths64)

Run the boolean operation and return the closed-path solution as a PolyTree64 hierarchy (outer contours with nested holes) plus the open-path solution as flat Paths64 (empty unless open subjects were added — Clipper2 returns open paths separately from the tree).

source
Clipper.execute_polytree_z — Function
execute_polytree_z(c, cliptype, fillrule) -> (PolyTree64Z, Paths64Z)

Run the boolean operation through the Z-aware entry point. Input tags supplied with Point64Z are preserved, while vertices invented at edge intersections are marked with Z_INTERSECTION. Closed paths are returned as a tagged tree and open paths as flat Paths64Z.

Narrow Point64 inputs may be mixed in; the C wrapper assigns them z = 0.

Offsetting

Clipper.ClipperOffset — Type
ClipperOffset(; miter_limit=2.0, arc_tolerance=0.0,
              preserve_collinear=false, reverse_solution=false)

A polygon-offsetting engine. Add geometry with add_path! (tagging each path with a JoinType and EndType), then execute with a signed delta.

arc_tolerance=0.0 selects Clipper2's automatic arc tolerance. Pass a positive value to set an explicit maximum deviation from the ideal arc.

The offset engine defaults preserve_collinear=false, while Clipper64 defaults to preserve_collinear=true. Throws ClipperError if the engine cannot be created.

Clipper.rect_clip — Function
rect_clip(rect::Rect64, paths) -> Paths64

Clip closed paths against the axis-aligned rectangle rect — Clipper2's RectClip, O(n) per path versus a full sweep-line boolean. The tile-cutting primitive for tiled operations over large geometry.

Each path is clipped independently: results are not unioned, and hole/owner relationships are not resolved. Follow with a boolean op per tile when input paths overlap or carry holes.
